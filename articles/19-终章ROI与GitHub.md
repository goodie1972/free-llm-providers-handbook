# 终章：从免费到便宜的 ROI，以及这个系列的去处

> 时效声明：本文 ROI 数字为个人体感估算，非精确财报。免费额度以官网实时为准（你看到时可能已经变）。

## 一、写到最后，算笔账

从 01 开篇到 18 合规红线，19 篇走完，你手里应该已经有一张"免费弹药库"地图了。最后这篇不教新平台，算笔 **ROI（投入产出比）** 账，回答一个最实际的问题：**免费到底值不值，什么时候该花钱**。

### 我自己的体感账

作为一个天天写代码、跑 agentic loop 的个人玩家：
- **纯免费层**（Groq + 硅基 + 魔搭 + unorouter + freellmapi 聚合），日常编码、原型、学 AI —— **每月成本 ≈ 0**；
- 代价是：限流要忍（17 篇）、模型天花板是开源权重（12 篇）、没有 SLA；
- 我愿意用"偶尔 429、偶尔等几秒"换"每月省下几百刀 API 费"，性价比极高。

### 什么时候该升级"便宜"

当出现这几种信号，免费层就不划算了，该往"便宜"走（11 篇路 2 的合规云、按量付费）：
- **生产流量**：服务真实用户、要 SLA → 免费层没有 SLA，断了要赔钱，比 API 费贵；
- **并发需求**：多用户同时调，免费层限流直接劝退（17 篇）；
- **需要前沿闭源旗舰**：Claude Opus / GPT-5 那批在付费层，免费池够不到（10、12 篇）；
- **敏感数据**：合规云加密通道（18 篇）。

**ROI 结论**：个人探索期，免费层 ROI 无限高；一旦进入"生产 / 并发 / 前沿 / 敏感"任一维度，"便宜的付费"反而比"硬撑免费"更省钱——因为免费层的隐性成本（中断、封号、违约）会反噬。

---

## 二、台阶：免费 → 便宜 → 按量

别一上来就买最贵的。阶梯是这样：

1. **免费层**（本文 01–10、12）：个人底座，零成本；
2. **聚合 + 兜底**（13、14、15）：freellmapi 聚免费 + One API 闸门 + 付费 provider 兜底，免费为主、付费保底；
3. **合规云按量**（11 路 2）：企业/生产，签约、合规、数据清晰；
4. **专属/私有部署**（Ollama 本地，08 篇）：数据不出机，敏感场景终解。

每一步都是"前一层的痛点"推着你往上走，不是一步到位。别焦虑，按自己当前阶段站好那层就行。

---

## 三、这个系列的去处：GitHub 永久 repo

免费额度最大的敌人是**时效**——今天写"290 家"，明天可能变。所以我把这个系列沉淀到一个能长期更新的地方：**GitHub repo `free-llm-providers-handbook`**（名字以实际建库为准）。

它长这样：
```
/articles/        每篇 markdown 正文（就是你现在读的这些）
/assets/screenshots/   各项目自有截图（本机访问后实拍，不搬别家图）
/data/           免费LLM对照表.xlsx + invites.md（邀请码汇总）
README.md        总览 + 篇目索引 + 数据日期 + 更新日志
CONTRIBUTING.md  投稿/纠错规范
```

**为什么放 GitHub 而不是只发公众号/头条**：
- 额度变动、站点关停，读者能提 Issue 纠错、提 PR 更新；
- 邀请码过期，社区维护，不误导人；
- 系列作为"活文档"长期沉淀，不受平台算法摆布。

**投稿机制**：
- Issues：纠错（额度变了、站没了）、补新项目；
- PR：新增测评、更新免费额度、补自有截图；
- 设 `good-first-issue` 引导新手；邀请码更新走社区 PR + 维护者审核。

每篇文末我都会引导：「完整可更新版见 GitHub」。公众号/头条是流量入口，repo 是永久沉淀。

## 五、给还在犹豫的你

如果你看到这还在纠结"要不要开始薅"：

- **第一步成本极低**：注册 OpenRouter / Groq / 硅基，拿 key，改个 `base_url`，半小时跑通（05、02 篇）；
- **别追求全**：19 家不用全注册，挑 2–3 个顺手的，配个 freellmapi 聚合，够用；
- **免费养个人、付费养生产**：这条线守住，你既省了钱又不踩线；
- **跟 repo 走**：额度变了来看更新，别拿本文当长期合同。
