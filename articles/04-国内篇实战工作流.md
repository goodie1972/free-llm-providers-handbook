## 二、我的"1+3"工作流：一个入口、三类任务

一个普通人（非开发者、非专业内容团队）每天用 AI，其实只干三类事：

| 任务类型 | 典型场景 | 对模型的核心要求 |
|---------|---------|----------------|
| **长文处理** | 日报/论文/行业报告/聊天记录 摘要、提炼、翻译 | 长上下文、输出稳定 |
| **代码/结构化输出** | 写脚本、改 bug、生成表格/JSON/Markdown | 代码能力强、遵循指令 |
| **轻量对话** | 灵感发散、文案润色、简单问答、多轮闲聊 | 响应快、成本低 |

我的做法：**一个 Python 脚本做入口，内部按任务类型路由到不同免费模型**。

这样做的好处：

- 不用记每家官网怎么登录；
- 可以批量处理文件、聊天记录、网页；
- 免费额度花完一家，换另一家继续跑；
- 为后面部署 `freellmapi` 聚合代理打下架构基础（第三辑会讲）。

## 三、各环节选谁：用前面三篇的免费额度拼一套方案

我现在的自用组合如下，全部基于国内免费档：

| 任务 | 首选模型 / 入口 | 备选 | 理由 |
|-----|----------------|-----|------|
| 长文摘要/翻译 | DeepSeek-V2.5 via 硅基流动 | Kimi / 通义千问 | 硅基 9B 以下长期免费，DeepSeek 上下文 128K，摘要结构好 |
| 代码/脚本/改 bug | DeepSeek-Chat 官方 | 智谱 GLM-4 / 豆包 | DeepSeek 代码能力强，官方免费额度够用 |
| 轻量对话/润色 | 智谱 GLM-4-Flash | 豆包 Lite / 通义 Lite | Flash 系列明确长期免费，响应快 |
| 批量跑任务 | 魔搭 Notebook CPU 免费 | 本地 Ollama（后续讲） | 24×7 挂机、跑定时任务不占用本地电脑 |

**这套组合的关键是"不押宝在一家"**。

- 硅基流动的价值是"一个 Key 调 100+ 模型"， deepseek-ai/DeepSeek-V2.5、Qwen、GLM 都能调，适合当"路由中枢"。
- DeepSeek 官方免费额度单独留着，专门给代码任务（官方模型最新、代码优化最直接）。
- 智谱 Flash 专门给轻量对话（免费且明确不限量）。
- 魔搭 Notebook 给需要定时批量跑的场景（比如每天早 8 点自动摘要 20 篇 RSS）。

如果你还没注册，建议顺序：硅基流动 → DeepSeek → 智谱 → 魔搭。

## 四、直接能跑的最小系统：50 行 Python 代码

下面是完整可跑的代码。只需要替换环境变量里的 Key。

```python
import os
from openai import OpenAI

# 任务路由表：按任务类型选 base_url + model
ROUTER = {
    "long_context": {
        "api_key": os.getenv("SILICONFLOW_API_KEY"),
        "base_url": "https://api.siliconflow.cn/v1",
        "model": "deepseek-ai/DeepSeek-V2.5",
    },
    "coding": {
        "api_key": os.getenv("DEEPSEEK_API_KEY"),
        "base_url": "https://api.deepseek.com/v1",
        "model": "deepseek-chat",
    },
    "chat": {
        "api_key": os.getenv("ZHIPU_API_KEY"),
        "base_url": "https://open.bigmodel.cn/api/paas/v4/",
        "model": "glm-4-flash",
    },
}

def ask(task_type: str, prompt: str, max_tokens=2048) -> str:
    cfg = ROUTER[task_type]
    client = OpenAI(api_key=cfg["api_key"], base_url=cfg["base_url"])
    resp = client.chat.completions.create(
        model=cfg["model"],
        messages=[{"role": "user", "content": prompt}],
        max_tokens=max_tokens,
        temperature=0.3 if task_type == "long_context" else 0.7,
    )
    return resp.choices[0].message.content

# 示例 1：长文摘要
article = """（把你的长文章贴在这里）"""
print(ask("long_context", f"用 5 条 bullet 总结以下文章，每条不超过 30 字：\n\n{article}"))

# 示例 2：写代码
print(ask("coding", "写一个 Python 函数，把一段文本按 500 字切成若干段，返回列表。"))

# 示例 3：文案润色
print(ask("chat", "把下面这句话改得更口语化：'该产品具备显著的降本增效能力。'"))
```

运行前安装依赖：

```bash
pip install openai
```

然后设置环境变量：

```bash
export SILICONFLOW_API_KEY="你的硅基 Key"
export DEEPSEEK_API_KEY="你的 DeepSeek Key"
export ZHIPU_API_KEY="你的智谱 Key"
```

Windows PowerShell 用 `$env:SILICONFLOW_API_KEY="..."`。

这套代码的核心就两点：

1. **openai 兼容接口**：国内主流平台基本都已支持 `/v1/chat/completions`，所以你不需要学五六套 SDK。
2. **任务路由**：用 `task_type` 这个字符串决定调哪家。后面如果你想做更智能的路由（比如按上下文长度、按响应速度），只需要扩展 `ROUTER` 字典。

## 五、三个真实场景的 prompt 模板

prompt 比模型更重要。下面三个模板是我使用频率最高的，直接复制可用。

### 模板 1：日报/长文摘要（给 long_context）

```text
请阅读以下文章，完成两件事：
1. 用 3 句话概括核心观点（每句不超过 40 字）；
2. 列出 3-5 个可操作结论或值得关注的事实；
3. 如果文章涉及数据，请保留关键数字。

文章：
---
{粘贴文章}
---
```

### 模板 2：会议纪要整理（给 long_context）

```text
下面是一段会议语音转文字稿，请整理成结构化纪要：
- 会议主题（1 句）
- 参会人发言要点（每人 1-2 条）
- 待办事项（谁 + 做什么 + 截止时间）
- 需要进一步确认的问题

转写稿：
---
{粘贴转写稿}
---
```

### 模板 3：周报生成器（给 coding，用代码批量跑）

```text
我本周完成了以下事项：
{粘贴事项列表}

请帮我写成一段周报正文，要求：
- 分"已完成"和"下周计划"两部分；
- 每条用"做了什么 + 产出/影响"的句式；
- 语气正式但不生硬，适合发给上级。
```

> 小提示：把周报模板写进上面的 `ask()` 函数，再加一个读取本地 Markdown 笔记的功能，每周五运行一次，就能自动生成周报草稿。

## 六、省钱与避坑：让免费额度滚起来

### 1. 别用重模型做轻活

很多人用 DeepSeek-V2.5 做简单问答，这其实很浪费。轻量对话请用 `glm-4-flash`、`豆包-lite`、`通义-lite` 这类明确免费的轻量模型。免费额度要花在刀刃上。

### 2. 把"长上下文"任务集中处理

免费额度往往有 RPM（每分钟请求数）限制。如果你有一批文章要处理，**不要一篇篇单独调 API**，而是写一个脚本批量读文件、合并 prompt、一次性输出，或者夜间用魔搭 Notebook 挂机跑。

### 3. Key 到期前做轮换

建议做一个简单的 Key 健康检查脚本：

```python
for name, cfg in ROUTER.items():
    try:
        ask(name, "hi")
        print(f"{name}: OK")
    except Exception as e:
        print(f"{name}: FAIL - {e}")
```

每周运行一次，哪家额度用完或接口变了，立刻换。

### 4. 代码和关键文件进 Git

这是上一篇也强调过的：免费额度随时可能调整，但你的 prompt 模板、路由配置、历史输出，一定要进 Git。模型可以换，你的工作流不能丢。

### 5. 三个不建议

- **不建议把免费额度用在生产服务**：免费是"启动资金"，不是 SLA。
- **不建议同时开七八个网页聊天**：用代码入口统一管，效率更高。
- **不建议不问时效就抄 prompt**：各家模型对同一 prompt 的理解有差异，本文模板请实测后再固化。
