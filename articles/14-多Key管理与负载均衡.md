# 多 Key 管理与负载均衡：用 One API 做闸门，给 freellmapi 配 Fallback

> 时效声明：本文操作基于 **2026-09-15** 核对的 One API / freellmapi 公开文档。面板按钮名、镜像版本以你执行时官网为准。

## 一、为什么到了"管理"这一层

前面 13 篇你把 freellmapi 跑起来了，各家免费 key 聚到一个端点。但用一阵子会冒出新问题：

- 一个 Groq key 限流了，freellmapi 那条通道空了，工作流还是断；
- key 越攒越多，哪个快到期、哪个被抽干，你根本记不住；
- 想给团队小伙伴也用，又不想把 key 裸发给他。

这就是"聚合"之后的下一关：**管理 + 兜底**。One API 干这个最成熟（12 篇讲过它是运营级分发），freellmapi 当其中一个 channel 接进去，再配一条 Fallback Chain——主渠道挂了自动切下一个。

我自己的体感：freellmapi 解决"零成本聚合"，One API 解决"管人和兜底"。两者串起来，免费层才真正稳。

---

## 二、One API 当分发闸门：它具体管什么

One API（12 篇提过，一行 Docker 起在 `:3000`）不是"再聚一次"，它是**在你和所有 channel 之间加一道带权限的门**：

- **令牌管理**：发一个 `sk-` 令牌给客户端，令牌能设有效期、额度上限、IP 白名单、可访问模型范围；
- **渠道分组**：把"免费池""付费兜底""某家专属"分成不同组，令牌只暴露你允许的组；
- **倍率与计费**：每个渠道设倍率，团队内部能算清楚谁花了多少；
- **渠道降级**：主渠道 429/5xx，自动切备用渠道——这正是 Fallback 的核心；
- **兑换码**：批量生成导出，做邀新/分发神器。

对个人玩家，One API 有点"杀鸡用牛刀"；但**一旦 key 超过 5 个、或想稳、或想给人用**，它是最省心的那道门。

---

## 三、把 freellmapi 当一个 channel 接进 One API

思路：freellmapi 已经在 `:3001` 跑着、吐统一 key，你把这个端点当成一个"上游渠道"注册进 One API：

1. One API 后台「渠道」→ 新建；
2. 类型选 OpenAI 兼容（或自定义），`base_url` 填 `http://<freellmapi地址>:3001/v1`；
3. key 填 freellmapi 给你的 `freellmapi-` 统一 key；
4. 这个渠道模型范围设成 `auto`（或你 freellmapi 里实际挂的模型）；
5. 保存。

此时 One API 令牌背后，就挂了"freellmapi 这个免费池"。客户端只配 One API 的 `:3000` 和 One API 令牌，完全不用知道底下是 freellmapi 还是别家。

---

## 四、配一条 Fallback Chain（关键）

单挂 freellmapi 还不够——它自己也是免费池，会限流/抽干。所以要给它配**备胎链**：

| 优先级 | 渠道 | 角色 | 触发切换条件 |
|---|---|---|---|
| 1（主） | freellmapi（免费池） | 日常零成本 | 429 / 5xx / 空响应 |
| 2（备） | 硅基流动 / OpenRouter 免费层 | 第二免费层 | 同上 |
| 3（兜底） | 某付费 provider（如火山/阿里云按量） | 生产兜底 | 免费全挂才用 |

One API 里把这几个渠道设为同一「分组」、按优先级排序，开「自动降级」。**主挂了毫秒级切备，免费全挂才掉付费兜底**——这条链建成后，你的编码工具基本不会再因为"免费层限流"断在半路。

> 注意：兜底那层是付费的，目的是"永不中断"而非"永远免费"。真个人玩，主+备两层免费够；团队/生产必加第三层付费兜底。

---

## 五、多 Key 负载均衡：把限流摊薄

One API 还能做**同 provider 多 key 轮询**：

- 同一个渠道（比如 Groq）挂 3 个 `gsk-` key，设「轮询」或「加权」；
- 请求按策略分到不同 key，单 key 限流被摊成 1/N；
- 某个 key 失效，自动踢出轮询，不拖累整体。

这对"免费层限流严"是直接的缓解——你手上有 2–3 个同家免费 key 时，负载均衡比"死磕一个"聪明太多。

---

## 六、踩坑提醒

1. **One API 自己要设管理员密码**。默认弱口令/空口令上线等于裸奔，第一次启动必改；
2. **Fallback 链别全堆免费**。全免费 = 全限流时一起挂，兜底必须有付费；
3. **倍率/额度别乱设**。给别人的令牌设额度上限，否则他一把跑光你所有 key；
4. **channel 健康检查要开**。One API 能定时探活，关了你就不知道哪个 key 悄悄死了。

## 结尾：一句真心的

管 key 这件事，前期嫌麻烦、后期真救命。我现在的稳态就是：freellmapi 聚免费池当主、硅基/OpenRouter 免费层当备、一个付费 provider 当兜底，One API 把这道门看住。免费层从"能用"变成"稳"，差的其实就是这一条 Fallback Chain。

下一篇（15）讲另一条路线——不靠"管 key"，而靠"智能路由 + 压 token"来榨干免费额度：9router 和 omniroute 这对兄弟，到底选谁。
