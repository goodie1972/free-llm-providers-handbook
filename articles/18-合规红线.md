# 合规红线：商用、版权、数据驻留，一次说清

> ⚠️ 免责声明：本文是**个人实践视角的合规提醒，不是法律意见**。各平台 ToS、各地法规随时变，涉及商用/敏感数据前，以官方条款和当地法律为准，必要时咨询法务。

## 一、为什么压轴讲合规

前面 17 篇把"哪里免、怎么管、怎么省"都讲了。但有个底线我一直没展开——**免费不等于随便用**。这几篇的纪律（12、14、17 都提过）到最后汇成一条：免费层的边界在哪。

这篇把三条最常踩的红线一次说清：商用、版权、数据驻留。不是吓你，是让你"薅得安心、不翻车"。

---

## 二、红线 1：商用——免费层大多禁止

**实测过，约一半免费模型的 ToS 限制"个人 / 家庭 / 非商业用途"。** 这是最容易被忽略的一条：

- 你拿 Groq 免费层写个个人脚本 → 没问题；
- 你拿它给公司客户跑付费服务、接进产品卖钱 → **踩线**；
- NVIDIA、OpenRouter、unorouter 的免费层，条款里都有"非商业"或"个人实验"字样。

**正解**：商用的唯一合规路径是一个字——**买**。走付费 API（或 11 篇讲的合规云），拿到商用授权，堂堂正正用。免费层养个人练习，付费层养生产，这条线别模糊。

---

## 三、红线 2：版权——生成内容的归属

很多人以为"AI 生成 = 随便用"，其实各模型对**生成内容的版权/商用授权**规定不同：

- 有的明确"你拥有生成内容"但限制转售模型输出训练；
- 有的对商用授权单独约定；
- 开源权重（DeepSeek / Qwen / Llama 系）相对宽松，但也要看具体许可证（R1 的 MIT、Llama 的社区许可各有边界）。

**实践建议**：
- 个人学习、内部原型：基本都能用；
- 商用、公开发布、训练自家模型：先查该模型的许可证/ToS 里"商用"那一条，别想当然；
- 把 AI 输出直接当"成品"卖（比如代写稿、生成图卖），确认平台允许再干。

---

## 四、红线 3：数据驻留——敏感数据别丢免费模型

这条最容易被"省 token"冲昏头：

- 把**客户名单、合同、商业报价、用户隐私**丢进任何免费模型，都是高危动作——免费层隐私承诺普遍弱，数据可能被用于训练或跨境；
- 合规做法：敏感数据要么**本地模型**（Ollama，08 篇讲过，数据不出机），要么**合规云的加密通道**（11 篇路 2）；
- 聚合网关（freellmapi / One API）里也别配敏感 key、别传敏感数据——你的 key 和流量都在那道门后。

**一句话**：免费模型处理"公开/脱敏"内容，敏感内容留给本地或合规云。这条和 11、17 篇的纪律一致。

---

## 五、红线 4：API 条款——别反向工程、别转售

- 多数平台禁止**反向工程、抓取、转售 API 服务**；
- 把免费层当"中转"二次卖给别人（做分销），基本违反 ToS；
- One API 的兑换码/分发功能，是给你**正经运营自己的服务**用的，不是让你绕开上游 ToS 转卖上游免费额度。

---

## 六、一张"该不该用免费层"的自检表

| 场景 | 免费层 | 付费/合规云 |
|---|---|---|
| 个人学习、写脚本、跑 agentic loop | ✅ 合适 | 浪费 |
| 内部原型验证 | ✅ 合适 | 可省 |
| 给客户/公司跑生产服务 | ❌ 踩 ToS | ✅ 必须 |
| 处理敏感/隐私数据 | ❌ 高危 | ✅ 本地/合规云 |
| 训练自家模型用输出 | 查许可证 | 看清授权 |
| 公开商用生成内容 | 查授权 | 看清授权 |

## 结尾：一句真心的

合规不是"束缚"，是"让你薅得久"。我见过太多人免费层用得正爽，商用一上、敏感数据一丢，号没了、单子黄了。这几篇反复强调的那句——**免费养个人、付费养生产**——就是这条红线的浓缩。下一篇（19）收口，咱们算笔 ROI 账，再把系列沉淀到一个能长期更新的 GitHub repo 里。
