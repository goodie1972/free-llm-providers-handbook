## 三、多账号轮换？先泼盆冷水

很多人第一反应是"多注册几个号轮换不就 unlimited 了"。这里必须说清楚：

**多数免费层 ToS 限制"个人/家庭用途"，明确禁止多账号规避限流**。你这么干，轻则封号、重则违约。所以"轮换"我不教违规多注册，只讲**合规范围内**的两种真解法：

**解法 1：多 key 轮询（合规，强烈推荐）**
同一平台你正经拿到的多个 key（比如团队分配、不同产品线），用 One API 负载均衡轮询（14 篇讲过）——把单 key 限流摊成 1/N。这是官方允许的"多凭证"用法。

**解法 2：备 2–3 个同能力模型**
限流是"单模型"维度的（尤其 unorouter 1/min/模型）。所以别死磕一个模型，备 GLM ↔ DeepSeek ↔ Qwen 这种同能力替补，一家满了切另一家。这叫"模型级轮换"，完全合规。

## 四、日常不踩限流的 4 个习惯

1. **常备 2–3 个同能力替补模型**，别把工作流绑死在一个免费模型上；
2. **agentic loop 必开 token 压缩**（9router/omniroute 的 RTK+Caveman，15 篇），输入 token 砍掉 20–40%，同等限流下多跑好几轮；
3. **错峰**：知道商汤每 5h 刷新、Kilo 每小时滚动，就把大批量任务拆到刷新点后；
4. **免费层只跑个人实验/原型**，生产流量老老实实走付费兜底（12、14、18 篇反复强调）。
